# Master PR Implementation Plan

This is the dependency-ordered implementation plan for the target architecture. It contains exactly 47 slices: 4 foundation, 6 point-in-time data, 5 evidence/signal, 6 backtest, 5 portfolio/risk, 4 execution-cost/liquidity, 4 experiment/alpha, 6 OMS/paper/reconciliation, 3 forward-gate, and 4 live. The IDs are stable references for phase implementation documents and the traceability appendix.

All changes before Phase 09 have no live broker side effect. `docs/config-only` means the slice can land without runtime code or external writes. `paper-only` means it may create local simulator/paper artifacts but must not submit a live broker order. `live-capable (Phase 09 only)` is restricted to Phase 09 and requires explicit approval, kill switch, and rollback evidence. Broker write remains false by default.

## Cross-plan merge rules

- No live-capable PR appears before Phase 09.
- Phase 07 may write only to an approved external PAPER endpoint through `paper_write_enabled=false` by default; `live_write_enabled` remains false until explicit Phase 09 authorization. Network egress is component-scoped: `data_capture_egress`, approved `model_provider_egress`, and `paper_broker_egress` may be enabled only for the approved path, while `research_tool_egress` and `live_broker_egress` remain denied.
- Every PR includes a migration/rollback note and an exact validation command.
- Every implementation file cross-references its assigned IDs; [`A_REQUIREMENTS_TRACEABILITY.md`](appendices/A_REQUIREMENTS_TRACEABILITY.md) maps IDs to tests and gates.
- A PR is merged only when its invariant tests pass, artifacts are reviewable, security boundaries are unchanged or explicitly approved, and the prior phase gate remains green.
